## 问题
Memory 目前只有设计文档，没有实体、业务逻辑、持久化实现、REST 路由或 MCP 工具。需要先冻结它解决什么问题、不和 Pin / RepoWiki / 对话日志抢职责，再谈表结构和接口。Workspace 出现之后，还要冻结记忆挂在哪一层——挂错了，生活空间的决定会在工作空间被检索到。

## 方案
1. **Memory 只保存需要跨会话继续遵守的决策性知识。**
   卡片字段包括标题、Markdown 正文、决策原因、适用范围、优先级、所属空间、可选的来源项目、标签。临时对话、文件内容、执行日志不进入 Memory。

2. **隔离键是 `workspace_id`，不是来源项目。**
   创建接口必须带合法空间 ID，禁止雪花零值。来源项目选填；若填写，该项目必须属于同一空间，否则拒绝写入。缺省来源项目不表示「全实例可见」。Memory 不调用 `WorkspaceLogic`，归属写在卡片字段上，与 Project 挂 `workspace_id` 同一层，不是跨域编排。

3. **查询默认只返回当前空间的 `active` 卡片。**
   列表、条件查询、MCP 检索必须带空间过滤。禁止接口在未传空间时扫全实例。需要看某张卡片时按 ID 读详情，详情响应带 `workspace_id`，不靠「全局记忆」兜底。

4. **写入由 Agent 或用户显式触发。**
   系统不从会话自动抽取记忆。未经确认的推断不得变成长期约束。

5. **生命周期采用 `active`、`deprecated`、`archived`。**
   默认查询只返回 `active`。被替代的记录进入 `deprecated` 并保留历史。仅作留档的记录进入 `archived`。禁止用文档里的 `accepted` 表示「代码已部署」。

6. **PostgreSQL 保存完整卡片、标签及关联关系。**
   Redis 只在真实查询负载证明有必要后用于热点缓存，不作为首版正确性依赖。

7. **Memory 保持独立业务域。**
   不直接调用 RepoWiki、Q&A、Pin 或 Preview。Agent 通过 MCP 组合。首版提供显式创建、条件查询、详情读取、更新和删除；REST 给控制台，MCP 给 Agent。接口命名在实现前按当前工程规范重确认，不复制旧 Wiki 参考值。删除非默认空间时，该空间下的 Memory 卡片不得默默出现在默认空间的查询里——具体删、迁、归档见待定，选定之前禁止实现跨空间可见。

## 不做什么
- 不自动把每轮对话写成记忆——噪声会淹没真正需要长期遵守的决定；
- 不把 Memory 做成跨项目消息队列——定向通知和 FIFO 消费属于 Pin；
- 不把记忆做成跨空间默认检索——生活空间的决策不得出现在工作空间的查询结果里；
- 不存储代码文件或生成的 Wiki 页面——代码知识读取属于 RepoWiki；
- 不在首版加入向量数据库——现有需求可先由结构化过滤和 PostgreSQL 文本检索验证；
- 不让 `accepted` 状态等同于「代码已部署」——文档共识与实现状态必须分开记录；
- 不在 Workspace 身份落地时实现 Memory 实体或 API——本文件只冻契约。

## 备选

| 方案 | 否决原因 |
| --- | --- |
| 自动从所有会话提取记忆 | 无法可靠区分临时信息、猜测和已确认决定 |
| 复用 Pin 表保存记忆 | Pin 的一次性消费语义与长期检索、废弃和归档语义冲突 |
| 直接把 ADR 文件当运行时 Memory | ADR 适合仓库内长期决策，但不能跨项目条件检索和 MCP 写入 |
| 首版引入向量数据库 | 增加部署与一致性成本，尚无检索质量数据证明必要 |
| 记忆只挂来源项目、靠 Project.workspace_id 间接隔离 | 违反方案第 2 条；无来源项目的空间级决策无处安放 |
| 查询不传空间就返回全实例 | 违反方案第 3 条；生活/工作决策串读 |

## 待定
- 标签采用独立实体还是 PostgreSQL 数组——阻塞数据模型设计；
- 删除采用物理删除还是软删除——阻塞审计与保留策略；
- 关键词检索采用 PostgreSQL 全文索引还是首版 `ILIKE`——不阻塞领域边界评审，阻塞性能验收标准；
- 删除非默认 Workspace 时，该空间下 Memory 卡片是拒绝删空间、随项目迁到默认空间、还是随空间一起归档——阻塞 Memory 实现，不阻塞 RFC-0003 身份评审。
