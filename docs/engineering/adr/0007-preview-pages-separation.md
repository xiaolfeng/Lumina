## 背景
当前 Lumina 的 Preview 模块（`PreviewSession` / `PreviewFile`）定位为 Agent 与用户之间轻量、即时、交互式的原型走查与视觉验证通道。原有实现采用 Query 参数路由（`/preview?session=<hash>&file=<filename>`），在实际协同中暴露出若干架构瓶颈：
1. **生命周期与心智混淆**：临时草稿与高质量持久页面共用同一易失性会话实体，导致 7 天 TTL 定期清理会误删团队沉淀的高质量页面；
2. **相对路径解析天然断裂**：在浏览器与 `iframe` 中，基于 Query 参数的 URL 在处理 HTML 内部同层相对跳转（如 `<a href="tokens.html">`）或静态资源（如 `<link href="style.css">`）时极易发生路径截断或跨级错乱，迫使前端引入复杂且脆弱的运行时拦截逻辑；
3. **交付体验割裂**：带参数的 32 位 Hash URL 难以识记与分发，且界面强制暴露调试工具条与代码查看器，无法满足向最终用户交付纯净展示页面的诉求。

因此需确立 Preview 与 Pages 的清晰架构边界、契约分层、路径式寻址规范与两态界面交互标准。

## 决定
1. **Preview 与 Pages 属于同一业务域下的「草稿工作台」与「发布交付物」两层形态，并施行分级权限隔离。**
   - **Preview 强制登录鉴权**：`PreviewSession` 属于内部研发与 Agent 协作草稿工作台，**必须经由控制台登录态认证（Console Auth / Bearer Token）方可访问**，未登录请求直接重定向至登录页或拦截为 401，严禁内部草稿裸露在公开互联网；
   - **Pages 交付态与可选密码保护**：Pages 作为项目级持久化静态发布实体，绑定所属 Project，拥有全局唯一的语义化路由 Slug；**访问权限策略（公开访问 vs 密码保护）由管理员在控制台管理端（`/console/pages`）独立配置**，禁止将安全策略与密码设置侵入开发者的轻量晋升（Promote）弹窗；
2. **Pages 必须通过快照晋升（Promotion Snapshot）创建或更新。** 从 Preview 晋升为 Pages 时，必须将当前会话的文件全量深拷贝为独立的不可变快照（包括 HTML 入口、Markdown、CSS、JS、静态资源），并记录来源会话与版本序列；禁止 Pages 运行时直接符号链接或引用易失的 `PreviewFile` 记录，防止后续草稿迭代意外污染已发布页面；
3. **全面采用全路径语义化寻址（Path-based Routing），废弃 Query 参数寻址。**
   - **Preview 工作台路径**：统一采用 `/preview/:session_hash/*filepath`（如 `/preview/7f8a92b104c8/index.html`；缺省路径时由后端/前端自动重定向至首个可用 HTML 入口）；
   - **Pages 展示态路径**：统一采用 `/pages/:project_name/:slug/*filepath`（如 `/pages/lumina/design-system/index.html` 或 `/pages/lumina/design-system/tokens.md`）；
   - **页面内相对链接原生支持与地址栏双向同步**：路径式寻址天然兼容 Web 标准的相对路径解析（`./` 与 `../`）；页面内超链接（如 `<a href="components.html">`）在点击时被原生触发或无刷新截获，在平滑切换画布内容的同时，将浏览器地址栏与工具条路径同步更新至目标文件，彻底消除旧版 Query 形式下「页面跳转后地址栏不刷新、无法精确书签直达」的断裂体验；
4. **UI 视图架构与用户心智彻底解耦。**
   - **Preview 采用工作台模式（Workbench）**：
     - 保留左侧完整文件树侧栏（Sidebar）、顶部调试工具栏（代码与渲染双态查看器、WebSocket 实时通信状态、草稿 TTL 倒计时提示），以及显式的「🚀 晋升为 Pages（Promote to Pages）」操作入口；
     - **自适应视口容器与双态切换**：
       - **视口渲染态**：桌面模式采用无边框全平铺（零留白损耗）；平板与手机模式在顶部预留优雅呼吸留白，设备内部具备 y 轴自适应上下独立滚动容器，呈现立体悬浮拟真卡片，并**支持拖拽右边缘自由拉大缩小（Freeform Drag Resize，320px~1200px）**，便于全断点响应式走查；
       - **源码检查态**：点击进入源码检查时，**界面默认自动缩回桌面全宽，并动态隐藏平板/手机端型切换器**，确保代码阅读与排错拥有充足横向宽度；切回视口渲染时无感恢复端型切换控制；
   - **Pages 采用展示模式（Showcase）与专属交互右侧抽屉**：
     - **沉浸式全屏渲染**：默认移除顶部调试工具栏、视口缩放框和底部控制条；
     - **右侧常驻微明胶囊与交互抽屉**：页面右上角保留极简悬浮徽章（Lumina Pages Pill），展开后提供元信息与文件快速直达；
     - **可直接渲染页面直切区**：抽屉上半部分突出展示 `.html` 与 `.md` 文件清单，支持**一键直接点击切换画布渲染界面**；
     - **不可直选渲染资源折叠区（高级 · Advanced）**：抽屉下半部分以可折叠手风琴形式收纳 `.css`、`.js`、`.json`、`.svg` 等底层辅助资源，点击可弹出源码查看器（Code Inspector），避免干扰普通读者的浏览动线；
5. **生命周期与清理策略单向解耦。** 临时 Preview 会话的到期归档、批量清理或手动删除，不得影响基于该会话发布的所有历史 Pages 记录；Pages 的下线必须走显式的生命周期变更（`published` / `archived`）；禁止对已发布 Pages 实施基于 TTL 的自动清除；
6. **单二进制内建交付、安全沙盒隔离与 Pages 密码门契约。**
   - Pages 运行时继续遵循 Lumina 单二进制嵌入与沙盒隔离契约（`iframe sandbox="allow-scripts"`），不依赖外部静态托管基础设施；必须对文件 MIME 与单文件大小（维持 256 KiB 上限）执行同等安全校验，严禁允许未经校验的服务端动态脚本或模板注入；
   - **密码门（Password Gate）安全机制**：选择密码保护模式的 Pages，密码经哈希加盐存储于持久层；未通过认证的访客访问 `/pages/:project_name/:slug/*` 时被统一重定向或拦截至微明密码门界面；输入正确密码后下发安全签名的 Session Cookie，会话期内免密畅通访问该快照下的全量页面与资源；复用现存 Wiki Reader 密码门设计，保持系统架构统一；
7. **Fork 溯源绑定与版本递增晋升闭环。**
   - **溯源上下文透传**：从 Pages 执行 Fork 操作时，新创建的 `PreviewSession` 必须写入 `source_page_id` 与 `source_version_id`，工作台明确显示当前为该页面的迭代草稿；
   - **智能晋升双态**：无溯源会话晋升时走「创建全新 Page」流程；带有溯源关系的会话晋升时自动进入「发布新版本」流程，默认锁定目标 Page，自动建议递增版本号（如 `v1.1.0`），提供更新说明输入并默认勾选「立即设为生效版本」；
   - **指针式原子切换与无损回滚**：`Page.latest_version_id` 担当当前线上生效版本的单一事实指针，线上访问统一由该指针解析；切换生效版本仅需原子变更指针，零文件搬迁，且历史快照永远不可变，随时支持秒级回滚。

## 后果
- 得到：明确区分了「敏捷探索草稿」与「稳定持久成果」；路径式路由解决了静态多页面跳转与相对资源引用的痛点；Pages 右侧抽屉既保证了多页面（HTML/MD）流畅浏览，又兼顾了极客与开发者查看 CSS/JS 资源的高级诉求；
- 失去：不能在修改 Preview 文件后自动实时同步到 Pages（必须经过显式发布快照更新）；后端与前端路由层需支持通配路径匹配（`/*filepath`）；
- 违反时暴露方式：清理过期会话时导致已发布页面 404；HTML 内链接相对跳转后落入无效 Query 导致 404；最终展示页面中出现内部代码调试抽屉；草稿编辑中的语法错误或半成品直接暴露在生产访问链接中。

## 否决项
- **保留 `?session=<hash>&file=<path>` 的 Query 寻址**：在 iframe 或子页面相对跳转时会导致 `href="subpage.html"` 相对基准错乱，必须依赖脆弱的 URL 重写；
- **仅在 `PreviewSession` 上添加 `is_permanent` 标记替代独立 Pages**：会导致草稿生命周期、实时同步广播逻辑与正式发布态强行缠绕，无法支持版本回溯与不可变快照；
- **Pages 页面完全砍掉文件列表，单页只能孤立查看**：对于由多个 HTML 或 Markdown 组成的原型集合，读者无法在页面内切换章节，可用性极差；
- **将所有 CSS/JS 与 HTML/MD 扁平平铺在 Pages 侧边栏**：导致非展示性代码文件大量稀释视觉焦点，丢失展示态的优雅质感。
