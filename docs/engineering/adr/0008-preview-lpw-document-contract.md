# LPW 文档文件与专用组件契约

> 状态：proposed · 承接 [LPW 社区实现调研](../research/0002-preview-lpw-community.md)。
> 2026-09-14 确认文件与组件契约；2026-09-20 补充 Pages 与 React 直渲边界；2026-09-21 按现有 v1.0 实现补充共享包归属、布局容器、批注与诊断约束。当前 `web/src/components/preview/lpw/`、`resources/lpw/schema/v1.json` 与 `preview_lpw_*` 已构成 v1.0 基线；后续能力以新格式版本演进，不回写已发布的 v1.0 语义。

## 背景

Lumina Preview 需要介于简单 Markdown 与自由 HTML 原型之间的文档表达：AI 声明内容块和参数，Lumina 提供稳定的排版与交互。社区已有类型化 JSON 映射组件的实现；本记录约束 LPW 的文件语义、组件责任与接入边界，不重新定义通用 UI 协议。

## 决定

1. **`.lpw`（Lumina Preview 文件）存储 UTF-8 JSON 文档数据，由 Lumina 发布的版本化 JSON Schema 约束。** 文档声明格式版本，系统按受支持版本选择 Schema；文件不能自行提供校验规则来绕过约束，也不能通过 Schema 声明注册可执行组件。发布后的同一格式版本不得改变已有类型和参数的含义；不兼容修改必须使用新版本。具体版本字段、Schema 方言和兼容升级方式留待详细设计，不能在缺少版本支持时猜测解析。

2. **LPW 的下一格式版本把内容节点严格分为同级的 `layout`、`container`、`block` 三类，并固定单向层级。** 根内容流可以出现三类节点；`layout` 只能直接包含 `container` 或 `block`，`container` 只能直接包含 `block`，`block` 是完整原子内容且不能包含 children。禁止 Layout 嵌套 Layout、Container 嵌套 Container、Container 包含 Layout，以及 Block 获得子树。`type` 对应已注册专用组件，`kind` 决定结构职责。现有 v1.0 的递归容器契约继续兼容读取；新版本不继承任意递归语义。

3. **LPW 专用组件库拥有独立的类型注册表和公开参数契约，核心实现归属 `@lumina/components/lpw`。** 文件只能调用明确注册的组件；Preview 工作台、Pages 展示态与 Q&A 内嵌只负责获取文件、选择入口和提供宿主上下文，必须消费同一共享实现，禁止在 `web/`、`web-wiki/` 或其他宿主复制解析器、注册表、块组件和视觉样式。专用组件允许复用 `@lumina/components` 的 UI、Markdown、Lucide 图标和主题原语，禁止把整个通用组件库、内部 React 组件名或全部底层 props 自动暴露给文件。每个可发布类型必须同时具备参数 Schema、渲染实现、用法说明、有效与无效样例；Schema 和实现不一致时不能宣称该类型已支持。宿主相关能力通过窄接口注入，不能让共享包反向依赖控制台业务状态。

4. **文档排版与组件视觉由 LPW 组件库负责，文件只选择契约允许的语义变体。** 例如提示级别、内容组织方式和表格列配置可以成为参数；任意 CSS、`className`、样式字符串、HTML 执行入口和事件代码不能作为通用扩展参数。允许展示源码文本，也允许 Markdown 的安全内容渲染；“展示代码”不等于“执行代码”。即使 JSON Schema 校验通过，组件仍必须处理文本、链接及媒体的安全边界，不能直接把不可信参数展开为 DOM 属性。

5. **LPW 首版交互限于阅读所需的本地行为，由可信组件实现。** 标签切换、折叠、表格排序筛选和图表悬浮等可由组件契约开放；这些行为不写回 `.lpw`，不形成业务提交或 Q&A 回答。文件不声明脚本、事件处理程序、表单提交、业务接口或 MCP 调用，也不引入通用数据源、状态表达式及绑定语言。“按数据映射”仅表示 JSON 参数传给对应组件；后续媒体加载策略需另行设计，不得借媒体参数提供任意请求能力。

6. **LPW 校验与渲染失败必须可见、可定位，不能静默丢失文档内容。** 公共上传逻辑负责版本与内容校验，非法文件不能按有效 LPW 写入并对外宣布可评审；前端渲染入口仍需检查所支持的版本和组件能力。错误至少能定位到 JSON 路径并说明原因；无法解析 JSON 时提供文档级错误。未知类型、错误参数、非法嵌套、渲染异常和资源超限不能只写控制台日志后丢块。上传失败不得覆盖已有有效文件；保留旧内容时必须说明更新失败，不能把旧内容当成新版本。组件能力、嵌套和资源限制需要在详细设计中补齐，不能把 Schema 合法等同于全部校验完成。

7. **LPW 是现有 Preview 的增强格式，有效 `.lpw` 必须能独立成为预览入口，不依赖额外 HTML。** 继续使用 Preview 会话、文件、上传覆写和 `preview_sync` 通知机制，保留 Markdown、HTML、SVG 与代码文件的原有用途；HTML/SVG 的既有沙盒边界不因此放宽。实施时必须统一文件识别、MIME、入口选择、MCP 工作流说明及前端文件分发；Preview 工作台（登录态）、Pages 展示态与版本快照（晋升后 `.lpw` 随文件进入 Page 快照，展示态将其视为可直切渲染的页面）、Q&A 中已有 Preview 引用都必须正确处理 LPW，而不是把原始 JSON 交给 HTML iframe。Q&A 引用继续使用 `session_id + file_id`，仅复用显示能力，不建立 Preview 对 Q&A 的业务编排。沿用现有扁平文件名及 256 KiB 单文件限制；多个可评审文件的入口选择规则留待详细设计。

8. **LPW 的首选运行环境是 Lumina 前端的 React 直渲管线，与 Markdown 同级。** `.lpw` 经前端文件分发（现 `PreviewFileViewer` 一类）识别后交给 `@lumina/components/lpw`，在 React 组件树内渲染；Preview 工作台、Pages 展示态与 Q&A 内嵌必须复用同一分发与渲染实现。禁止把「先转 HTML 再进沙盒 iframe」作为 LPW 的主交付路径，iframe 沙盒仅保留给 HTML/SVG；导出静态 HTML 最多作为附加能力，不得成为唯一可见形态。原因：直渲管线能直接消费共享排版与主题，并保留组件本地状态、块级错误边界和组件级测试。非 React 宿主的支持不在本契约承诺范围内。

9. **`layout` 是纯结构编排，`container` 是受控美化整体，`block` 是完整原子内容。** Layout 负责左右、上下、交错、规则网格、Bento、报纸多栏、图文环绕与响应式阅读顺序，不提供标题、边框、背景、折叠或正文；其直接子节点可以是 Container 或 Block。Container 负责章节、面板、折叠和页签等完整视觉外壳，只能按 `type + variant` 接受已登记的 Block 能力组、数量和顺序，不能作为任意 Block 集合的通用包装器。Block 自己完成一项内容用途。真正的「方形媒体 + 异形正文」只允许 `editorial-wrap` 直接组合 image Block 与 markdown Block；Container 不参与正文浮动，Bento 的异形轮廓由多个完整矩形节点拼合。所有模式、变体和合法子节点组合必须由 Schema、注册表元数据与 logic 校验共同约束。

10. **批注是 Block 级元数据，由统一装饰层呈现，不能侵入每种 Block 的业务属性。** 每个 Block 可以携带枚举批注；Layout 与 Container 不携带文本匹配批注。批注至少包含类型、说明和零个或多个文本匹配器。批注类型由版本化 Schema 收敛，正文匹配器使用受限正则并明确目标字段。统一装饰层负责 Block 标记、波浪下划线、无障碍说明与悬停/聚焦详情；不能使用批注改写原文、执行脚本或匹配代码、图表、图片等非文本数据。正则必须限制长度、标志与执行预算，非法或超预算模式作为可定位的批注错误显示，不能阻断原 Block 正文。

11. **LPW 的视觉结构必须表达语义，装饰线、标题与折叠容器不能互相伪装。** 标题层级使用字号、色阶、左侧强调边与受控 Lucide 图标建立辨识；图标允许显式枚举，缺省值按标题级别确定，禁止依赖语言关键词猜测内容语义。`details` 使用明确的可展开容器、箭头与状态文案；`section` 保持章节语义。横线只用于显式 `divider` 或必要的数据表格边界，文档壳、标题、章节、卡片和折叠内容不得叠加无语义的粗黑横线。

12. **节点级错误必须同时说明位置、类别、组件与原因，并保留可安全查看的输入摘要。** 渲染器为每个 Layout、Container 和 Block 计算稳定的索引路径与 ID 父链；未知类型、层级非法、Container 变体不接受子 Block、Layout 槽位不兼容、组件异常与批注错误均在原位置呈现。诊断至少包含错误类别、文档路径、节点 ID、kind、type、组件显示名、原因和修复提示；属性摘要需要大小上限和敏感字段遮盖，不能把完整大文本、媒体数据或潜在凭据直接回显。生产界面不展示运行时堆栈；开发环境可以在折叠区提供调试详情。

13. **Mermaid 块以可读视口为目标自适应，保留图形比例并提供超宽图导航。** SVG 使用 `viewBox` 在容器内等比缩放，默认宽度填满且高度自动；复杂图允许横向滚动、适应宽度、原始比例和全屏查看。实现不得用非等比拉伸换取铺满，也不得依赖修改 Markdown 全局渲染规则来修复单个 LPW 块。

## 后果

- AI 可以直接表达文档块和参数，文档排版由专用组件维护；支持更多内容类型需要 Lumina 增加组件，不能由文件临时编写实现。
- 文件契约与渲染依赖分离。后续可选择社区渲染器或有限的自建分发，但都必须满足同一 Schema、专用组件边界与可见错误要求；当前没有决定引入 json-render。
- 需要持续维护版本、Schema、注册表、说明与样例的一致性，并验证前后端对同一组有效和无效文档的判断一致。
- 核心渲染能力进入 `@lumina/components/lpw` 后，宿主之间共享同一注册表、布局契约、批注层与错误语义；共享包需要承担 ECharts、Diff 等 LPW 运行时依赖的按需加载和包体治理。
- `layout` 提供面向文档的高层构图能力，同时失去任意 CSS 拼版自由；新增模式必须先定义直接子节点 kind、槽位能力、移动端顺序和失败语义。
- `container` 以 variant 约束 Block 策略组，得到稳定的美化整体，同时失去任意 children 组合；需要新组合时先新增或扩展受审查的 variant。
- next 的最大结构链被固定为 Layout → Container → Block，解析、定位和移动端阅读顺序更可预测；v1.0 递归容器继续兼容读取。
- 方形媒体与异形正文环绕成为受控的双槽位模式；任意组件继续位于矩形布局槽中，避免浏览器重排、可访问性阅读顺序和多端渲染出现分叉。
- 批注会扩大 Schema、文本渲染与性能测试范围；匹配器必须受限并在不支持的块中明确拒绝。
- 诊断信息更可行动，同时需要遮盖与截断策略，防止错误界面暴露完整输入。
- 违反约束会表现为：上传成功却无法渲染、不同入口显示不同内容、移动端阅读顺序错误、升级后旧文失效、块静默消失，或文档参数获得未授权的执行与请求能力。后续验收必须覆盖这些失败路径，而不只检查有效样例。

## 否决项

- **让 AI 继续生成 HTML 作为 LPW 的内部实现**：重新引入排版和脚本编写负担，失去专用组件契约；独立 HTML Preview 仍是合法的自由原型格式。
- **把 LPW 做成任意 React/DOM 序列化格式**：底层布局与 props 会成为长期文件契约，与已确认的文档块颗粒度不符；专用组件内部使用 React 不受此限制。
- **用自带 Schema 或远程脚本让文件自行扩展组件**：文件会同时定义能力和批准自身能力；新增组件应由 Lumina 实现并发布。
- **直接把社区框架的全部状态、动作和消息协议纳入 LPW**：当前需求只有文档和本地阅读交互；借鉴注册表、版本与校验机制，或后续选用受限适配器，不在此否决范围内。
- **把 LPW 先转 HTML 再送入沙盒 iframe 作为主路径**：放弃 React 直渲后失去主题与排版复用、块级错误边界和组件级测试，Markdown 已验证的直渲管线也被浪费；附加性的静态导出不受此禁令限制。
- **只校验 JSON 语法，或遇到错误静默跳过块**：前者无法约束参数，后者会把不完整文档展示成完整结果。
- **把 LPW 核心继续留在 `web/` 并由其他宿主复制**：同一文件会在不同入口获得不同组件、样式和错误行为；宿主可以保留加载外壳，核心实现必须来自共享包。
- **让 Layout、Container 和 Block 任意递归嵌套**：三类职责会重新退化成通用 UI 树，校验、错误定位和视觉层级无法收敛；下一格式版本只允许 Layout → Container/Block、Container → Block。
- **把 Container 设计成允许任意 Block 的美化框**：不同 variant 会失去内容语义，生成方仍可拼出不协调组合；每个 variant 必须登记 Block 能力组、数量、顺序与重复策略。
- **让 Container 参与 Editorial Wrap 正文浮动**：Container 的边框、背景与交互外壳需要完整矩形边界；该模式只接受 image + markdown 两个直接 Block。
- **只提供 `grid` / `flex` 低层参数并把文档构图交给生成方猜测**：无法稳定表达报纸多栏、图文环绕、交错图文和 Bento 等常见版式，也无法约束阅读顺序与响应式降级。
- **允许任意块成为 L 形或参与正文浮动**：普通 React 组件无法安全拆分为非矩形流，容易破坏交互边界、焦点顺序和移动端阅读；异形环绕仅限媒体与可流式正文的受控组合。
- **让标题图标依赖关键词自动猜测**：同一标题在不同语言和措辞下会得到不稳定视觉语义；文件使用受控枚举显式选择，缺省只按层级给固定图标。
- **直接对已发布 v1.0 Schema 增加 `layout` 与批注字段**：破坏同版本兼容承诺；该能力进入新的格式版本，并保留 v1.0 读取与渲染。
- **在错误卡中输出完整 props 或生产堆栈**：大文本、外链参数或潜在敏感信息会被无边界暴露；诊断只呈现遮盖后的限长摘要。
